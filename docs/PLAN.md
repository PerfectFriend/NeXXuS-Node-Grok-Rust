# План: очередь, описание, майнер, диск, лук

Дата: 8 ноября 2026. Эталон поведения — Linux-нода 0.10.0. Новый смысл в эти пять частей не добавляется. Оплаты по-прежнему нет. Свой onion-адрес по-прежнему не сочиняется.

Состояние: этапы 1–4 закрыты лабораторными тестами `services` и вектором `vectors/smp-xftp.json`. Живой лук из этапа 5 в обычный тест не входит.

Каждый этап готов только когда названный прогон проходит. Компиляция этапом не считается.

## 1. Очередь SMP

Свой формат `nexxus-smp-v1`, не провод simplexmq.

Релей хранит чужой шифртекст и не больше 32 сообщений в очереди. Забрать очередь может только отпечаток, который её открыл. Чужой запрос остаётся без ответа, и у вызывающего это таймаут «Очередь SMP не ответила». В `smp.json` нет открытого текста.

Ключ сообщения: X25519 эфемерного ключа отправителя и публичного ключа очереди, HKDF-SHA256, соль пустая, info `nexxus-smp-v1`, затем XChaCha20-Poly1305.

Готово, когда три лабораторных узла повторяют `test-smp.mjs`: релей не видит текст, чужой не забирает, владелец открывает.

## 2. Описание XFTP

Свой формат `nexxus-xftp-v1`. В описании есть подпись Ed25519, хеш файла и идентификаторы чанков. Полей `host` и `port` нет: описание с ними отвергается, даже если подпись сходится.

Чанки едут как обычные чужие блобы. Сборка на приёме читает их с диска и сверяет хеш. Адресов узлов в описании нет.

Готово, когда два узла повторяют `test-xftp.mjs`: файл собирается, а в описании нет адреса. Вектор `vectors/smp-xftp.json` снят с Linux-ноды и обязан открываться здесь.

## 3. Майнер

Флаг `--miner`.

Объявление `nexxus-miner-v1|отпечаток|байты` подписывается ключом ноды. Принимается только подпись ключа Ed25519 из HELLO. Чужую подпись узел не верит.

Майнер не кладёт свои файлы в бесплатные копии. Чужой файл на него класть можно. Объявленный объём в этой версии фиксирован, как в эталоне: 64 МиБ. Это не проверка свободного диска и не продажа места.

Готово, когда прогон повторяет `test-miner.mjs`: у своего файла майнера `copies=0`, у файла обычного узла появляется копия.

## 4. Папка drive

`ДАННЫЕ/drive` — открытая копия сейфа, не зашифрованный том.

Положенный туда файл режется и записывается в журнал. Правка заменяет запись. Удаление из папки снимает файл с сейфа. Файл, записанный в сейф, появляется в папке. Индекс — `drive-index.json`. Каталог не становится тайником: кто открыл папку, тот прочитал файлы.

Готово, когда один узел повторяет `test-drive.mjs`.

## 5. Onion

Уже сделано в профиле `onion`: бинарник `tor`, адрес только из `hostname`, звонок через SOCKS5, лабораторный профиль отвергает `.onion`.

Не сделано и не входит в обычный `cargo test`: два настоящих v3 и одно сообщение через сеть Tor. Для этого на машине должен быть `tor` и выход в сеть. Адрес на этот прогон не подставляется. Нет бинарника — старт с ошибкой, как и раньше.

## Чего этот план не делает

- не считает квоту `S / 3` и не проверяет свободные 16 ГиБ;
- не вводит оплату и биржу;
- не делает общий чёрный список;
- не переписывает веб-панель;
- не тащит Android, пока эти четыре прогона на Rust не зелёные.

## Порядок работы

1. Чистые функции очереди и описания, вектор Linux.
2. Очередь на трёх узлах.
3. Описание на двух узлах.
4. Майнер.
5. Папка `drive` и снятие файла с журнала.
6. Живой лук — только руками, отдельной командой, когда на хосте есть `tor`.
